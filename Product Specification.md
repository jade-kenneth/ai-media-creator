## 0. What it is

A general AI video creation workspace, made of studios. **Affiliate Studio** (under Marketing, the first) turns a real product into an approved, fact-checked short-video script and a plain-text creator brief. Batch 2 adds voice, scene editing and 9:16 MP4 export. **Entertainment Studio** (R27–R28, 2026-09-26; §3.23) turns a genre, a premise and a cast into a short story video (drama, action, comedy and more) on the same script, media, voice, editor and export tools, with no product. Shared surfaces never assume one studio.

**Product stack (as built in this repository):**

| Layer | Implementation |
| --- | --- |
| Client | `apps/app-web` — Next.js 16 App Router, React 19, TypeScript, Tailwind v4, shadcn/Radix primitives (`components/ui`), TanStack Query, graphql-request, GraphQL Code Generator, react-hook-form + zod, Sonner, Lucide |
| API | `apps/app-api` — NestJS 11, Apollo GraphQL (schema-first SDL in `src/graphql/schemas`), Mongoose through the repository layer (`src/libs/mongoose-repository.ts`), zod validation at the boundary |
| Database | MongoDB via **`MONGODB_URI`**, database **`ai-creation-platform`** (sanitized target; the value is never written in docs or code) |
| Files | AWS S3 (existing `s3` module): presigned PUT uploads, signed GET reads, server-generated keys |
| Background jobs | `GenerationJobs` collection; a worker inside the API claims queued jobs on an interval with the existing `@nestjs/schedule` + scheduler-lock pattern; clients poll |
| Text generation | A server-side provider adapter with JSON output: OpenAI (`OPENAI_API_KEY`, `OPENAI_TEXT_MODEL`), Anthropic (`ANTHROPIC_API_KEY`, `ANTHROPIC_TEXT_MODEL`), DeepSeek (`DEEPSEEK_API_KEY`, `DEEPSEEK_TEXT_MODEL`, default `deepseek-v4-pro`) or MiniMax M3 (`MINIMAX_TEXT_API_KEY`, `MINIMAX_TEXT_MODEL`, default `MiniMax-M3`). `TEXT_PROVIDER` picks one when several are configured; otherwise the first configured is used. `TEXT_FALLBACK_PROVIDERS` is the ordered fallback chain; legacy `TEXT_FALLBACK_PROVIDER` remains supported for one fallback. The MiniMax text key is a Token Plan Subscription Key and is separate from the pay-as-you-go video key. Anthropic approved by the product owner 2026-09-24; DeepSeek and MiniMax fallback added 2026-09-27 |
| Auth | Existing JWT access + refresh sessions; Google ID-token sign-in (GraphQL `loginWithGoogle`) extended to provision a first-time creator |
| Voice (Batch 2) | ElevenLabs, server-side (`ELEVENLABS_API_KEY`, `ELEVENLABS_MODEL_ID`, `ELEVENLABS_VOICE_IDS`): per-scene speech with word timing, and forced alignment for uploaded recordings (R16) |
| Render (Batch 2) | FFmpeg and ffprobe in a separate media worker process (`apps/app-api/src/worker.ts`) that claims voice and render jobs from the same `GenerationJobs` collection (R17, R18) |

> **API convention (read this first).** All app data flows over **GraphQL**: SDL first in `apps/app-api/src/graphql/schemas/*.gql`, `pnpm --filter app-api generate-graphql-types`, resolver → service → repository; on the client, operations live in `apps/app-web/react-query/<domain>/graphql/*.ts`, types come from `pnpm --filter app-web codegen`, and hooks are built with `defineQuery` / `defineMutation` in `react-query/<domain>/<domain>-operations.ts`. The only REST surfaces are the existing session endpoints (`/session/refresh`, `/session/logout`; the boilerplate's `/session/authenticate/google` stays but the web app does not call it) and the S3 presigned-URL PUT made directly from the browser to S3.

> ⚠ **Origin of this product's UI, behavior and scope:** `design/` — the [Design Reference](design/handoff/AI%20Creation%20Platform%20Design%20Reference.md), `design/system/` and `design/planning/`, written in prompt-only mode from `design/CLAUDE_DESIGN_PROMPT.md`. There are no prototypes; the Design Reference's per-screen specs are the fidelity contract. The boilerplate contributes **backend plumbing only** — build on it, don't scaffold from scratch, and **discard its UI entirely** (admin, super-admin, push tester, organizations and account-deletion screens, its theme and demo copy).

> **Database.** Everything is wired through `MONGODB_URI` (database `ai-creation-platform`). The local configuration is present and connectivity was verified on 2026-09-24 without recording its value. The canonical demo data is seeded under the product owner's Google account (`SEED_OWNER_EMAIL`) and reruns idempotently — see §5. Google OAuth is configured, and a real first sign-in provisioned an account end to end on 2026-09-24.

### 1.3 Space, radius, elevation, sizing

4-pt scale (4, 8, 12, 16, 20, 24, 32, 40, 48, 64). Radii 6 / 10 / 14 / pill. Elevation `--e1` `0 1px 2px rgba(23,22,28,.06)`, `--e2` `0 4px 16px rgba(23,22,28,.08)`, `--e3` `0 24px 48px rgba(23,22,28,.18)`. Controls 40px (44 below 1024), small 32 (36), chips 32 (40); top bar 60; rail 232. Breakpoints: 640 / 768 / 1024 / 1200 (asides) / 1280.

### 1.4 Signature style moves

- Warm paper canvas with white cards (1px `--border`, 14px radius); depth comes from borders, and shadows only on overlays and hovered cards.
- Ink primary buttons; the flare accent appears only as a mark: the current-step circle, the logo dot, the avatar and empty-state tint.
- Paid buttons carry a **cost segment**: a 1px divider then the mono estimate (“3 credits”).
- Selection = ink ring + check glyph, never colour alone.
- Unreviewed facts: warm tint + 3px warning inset bar. Flags: warning callout with a 3px left bar.
- Mono for everything the creator compares (durations, credits, counters).

### 1.5 Imagery rule

Real uploaded media only. A project or asset without media shows a flat `--surface-sunken` tile with a 20px `--ink-3` film icon. No illustrations, gradients, stock photos or generated art stand in for media. The sign-in stage graphic is built from CSS shapes and is `aria-hidden`.

### 1.6 Motion

Per [motion.md](design/system/motion.md) (design-engineering values): `--ease-out cubic-bezier(0.23,1,0.32,1)`, `--ease-in-out cubic-bezier(0.77,0,0.175,1)`, `--ease-drawer cubic-bezier(0.32,0.72,0,1)`; press `scale(0.97)` 140ms on buttons; popover and dialog enter 180ms from 0.96–0.97 scale + opacity, exit 120ms opacity; drawer and sheet 280ms; menus instant; no `transition: all`; reduced motion → opacity only, instant scrolling.

### 1.7 Voice and tone

Plain, direct English; sentence case; verb-first specific buttons; errors say what happened, what was kept and what to do next; costs never hidden; “it drafts, the creator decides”. Full rules and vocabulary: [voice-content.md](design/system/voice-content.md).

### 3.19 Scene transitions — Design Reference §5.8, §5.9, §5.12, §5.14, §5.15 (approved 2026-09-25)

- **Status:** approved by the product owner 2026-09-25; build in Phase 23. Rests on R22 (the script model picks, within the rules below). The Design Reference absorbed it on 2026-09-25 (§5.8, §5.9, §5.14, §5.15); look and interaction live there.
- **Why:** brief §4 item 8 builds the draft from “real product assets, text, captions and transitions”, but the renderer joins scene segments with the concat demuxer (`-c copy`), so every scene change is a hard cut and the only motion is the photo slow zoom. Shot direction (§3.17) gives the creator a director's notes. This section adds the editor's notes: how each scene comes in. The script proposes them, the creator brief carries them to creators who edit elsewhere, and the render and preview play them.
- **Principle:** on TikTok, polished editing reads as pacing, not effects. Most scene changes stay hard cuts on the narration beat. Each other transition needs a reason, and the rules below cap them.
- **Out of scope:** free-form or custom transitions, custom transition lengths, cutting to the music's beat, sound effects (whoosh), a transition into the end card, and a timeline editor (brief §4, “a full multitrack editor” is outside the first release).
- Fidelity check: matches §5.8, §5.9, §5.12, §5.14 and §5.15 as revised, including versions and video edits from before transitions existed, and the first scene after a reorder.

**The four transitions** (each one describes how a scene *comes in*)

| Value | Label | What it does | Overlap |
| --- | --- | --- | --- |
| `CUT` | Cut | Hard cut, as today. The default | none |
| `PUNCH_IN` | Punch-in | Hard cut; the incoming scene starts at 115% scale and eases to 100% over 300 ms (`--ease-out` curve), centred. Stacks on top of slow zoom | none |
| `WHIP` | Whip | The outgoing scene slides out left as the incoming one slides in from the right (FFmpeg `xfade=transition=smoothleft`) | 250 ms |
| `DISSOLVE` | Dissolve | Crossfade (FFmpeg `xfade=transition=fade`). Only for time passing, e.g. before → after | 400 ms |

The first scene in edit order always opens without a transition, whatever its stored value. This also holds after a reorder moves a scene to position 1. The end card always comes in with a cut.

**Surfaces:** look and interaction live in the Design Reference, revised 2026-09-25: §5.8 (Transition in in the Shot direction fieldset, hints, “Opens the video.”, read-only suffix), §5.9 (`Transition:` rule), §5.14 (Transition in row on each scene card, preview transitions, reduced motion, first scene after a reorder) §5.15 (history details suffix) and §5.12 (Media direction line, Punch-in hint, clip warning that counts the next overlap; revised 2026-09-25).

### 3.20 Scene length follows narration; shoot plan on Media — Design Reference §5.8, §5.12 (requested 2026-09-25)

- **Why:** every script is narrated. Each scene has a narration line, and the Voice step reads it (AI voice or the creator's recording) or drops it (No voiceover). - **What it adds:** (1) a content style **Skit** that writes a short scene acted out by a cast, with spoken lines and a sound cue per scene and no narrator. (2) **Clip sound**: a scene's clip plays its own audio in the preview and the export, at a level. It is on by default in skits and off by default elsewhere, so existing videos don't change, and any style can turn it on (sandal steps under a voiceover). (3) A Voice source **Sound from your clips**: no voiceover, with captions from the spoken lines. (4) AI clip descriptions that carry the sound cue and the lines, so the clip is made with that sound.
- **Out of scope:** AI sound effects for photos or silent clips (R26 D3); AI voices per character (text-to-speech per speaker); timing captions to a clip's audio (per-clip forced alignment), so captions follow the script as No voiceover does; automatic ducking; sound carrying across a transition overlap; reference audio sent to the video service; a multitrack timeline and voice cloning (brief §4).

Much of what a story needs is already built for Affiliate Studio's Skit style: a cast, spoken lines acted as beats, sound cues, clip sound, AI clips that speak lines, Keep consistent items and a still carried from scene to scene. Entertainment Studio reuses all of it without the product.
- **What it adds:** (0) a **studio registry**: one typed definition per studio that the shared code reads, so the next studio is a new definition plus its own intake step; (1) studio-neutral shared surfaces: sign-in, dashboard, a **New video** chooser that lists the registry's studios, and a studio line on every project; (2) a **Story** step (genre, premise with three suggestions, cast, format) in place of Product, Facts and Strategy; (3) story scripts in Script Studio: story hooks and scene purposes, Acted or Narrated, no fact claims; (4) stories in the video steps: characters in Keep consistent, **Describe only** AI clips, an end line in place of the call to action, no `#ad`; (5) a story creator brief.
- **Cliffhangers (R29, product owner 2026-09-26):** every story's last scene ends on a cliffhanger (Production mapping row “Cliffhanger ending”).
- **Out of scope:** a product inside a story (D10); episodes or linked parts (superseded 2026-09-27: stories continue as episodes, §3.25, R31); AI voices per character; generated character portraits (D4); generated music; landscape presets (R14: TikTok 9:16 stays the only preset); a studio filter on the dashboard (it becomes worth adding at three or more studios); any other studio in this batch (Education, business and personal studios, and more, come later on the same contract). A studio that isn't built is not listed anywhere; nothing is shown as “coming soon”.
- **Unchanged:** every Affiliate Studio screen, rule, prompt and output. Existing projects, versions, video edits and exports read as Affiliate Studio and behave exactly as today.

### 3.24 Entertainment Story detail — Design Reference §5.17 (approved 2026-09-27)

- **Decision R30:** the product owner chose the recommended flow: one optional short detail guides the existing three-option premise job. AI does not create one final story directly; the creator still chooses one of three full premises. **Write my own premise** remains.
- **Outcome:** a creator can enter only a person, place, object or moment and let AI invent the larger premise and cast. The detail is context, not a premise, so it never unlocks Script by itself.
- **UI:** the Premise card gains **Story detail (optional)**, a two-row textarea (≤ 160), placeholder “e.g. Two strangers reach for the same umbrella.” and helper “A person, place, object or moment is enough. AI will build the premise and cast.” The before-suggestions line is “Add one detail, then get three complete story ideas—or write the premise yourself.” Exact layout, accessibility, responsive behavior and states live in Design Reference §5.17.
- **Behavior:** `Story.detail: String!` defaults to empty and autosaves through `updateStory`. The API collapses whitespace and returns `ValidationError` at `input.detail` with “Use 160 characters or fewer.” when invalid. `PremiseSuggestionSet.detail: String!` snapshots the normalized value; its computed `isStale` is true when genre or detail differs. Detail-only stale copy is “You changed the story detail after these premises were suggested.” “Suggest again to use the new detail.”
- **Generation:** `PremiseSuggestionsHandler` receives the detail and is told to expand it into three clearly different, complete premises with casts instead of paraphrasing it. Existing schema coercion, content rules, cliffhanger rule, credit, idempotency, failure, retry and cast-fill behavior remain.
- **Compatibility:** records without `story.detail` or a suggestion-set detail read as `''`. Affiliate Studio and later story steps are unchanged. Phase 32 owns the contract, prompt, UI, seed update and focused regression/Fidelity QA.

### 3.25 Story episodes — Design Reference §5.17, §4, §5.3, §5.8, §5.9, §5.14 (approved 2026-09-27)

- **Status:** requested by the product owner 2026-09-27 (“the entertainment should not just end with 5 scenes, it should continue like by episodes”). Decisions E1–E10 were drafted with a recommendation each and **approved by the product owner 2026-09-27 as recommended** (“approve as recommended”), recorded as **R31** (open decision 23 is resolved). This reverses the §3.23 out-of-scope line “episodes or linked parts” and R29's “Parts and series stay out of scope”. The rest of R29 stands: every episode ends on a cliffhanger except a final one. The Design Reference absorbed this section on 2026-09-27 through `/generate-design-request` (prompt-only): §4, §5.3, §5.8, §5.9, §5.14 and §5.17 now own look, copy and interaction, and where they differ from this section, the Design Reference wins. Build: Implementation Plan **Phase 33**.
- **Why:** a story is one 30–60 s TikTok video of 4–6 scenes (Hook, Setup, Build-up, Turn, Cliffhanger). R29 makes every story end on a cliffhanger “so viewers want the next part”, but there is no next part. The only workaround is duplicating the project, and then the AI knows nothing about what already happened.
- **Outcome:** from any story with an approved script, a creator can make **Episode 2**, then 3, and so on. Each episode is its own 30–60 s video. It picks up from the previous cliffhanger, keeps the cast and the looks they set, and ends on a new cliffhanger, until the creator marks an episode as the **Final episode**.
- **Unchanged:** the length of each video (30, 45 or 60 s, 4–6 scenes), the scene purposes, the hook types, the D6 story rules, credits per action, and every Affiliate Studio screen, prompt and output.

## 7. Non-negotiables

- [ ] Backend boilerplate reused (auth, sessions, GraphQL, repository layer, S3, scheduler locks); boilerplate UI discarded — no admin screens, neutral theme, dark mode or demo copy survive.
- [ ] Every built screen matches its Design Reference section exactly in visual and behavioral outcomes (the fidelity contract in prompt-only mode).
- [ ] No mock arrays, local copies of server records, fake persistence, fake delays or manual-only validation in the production path.
- [ ] Server state and writes use the GraphQL + codegen + TanStack Query path; forms use react-hook-form + zod; the API enforces validation, ownership and workflow gates (conflict errors), never only the client.
- [ ] Paid actions are idempotent (one job per intent), hold credits before work, charge on completion, release on failure.
- [ ] Model output is untrusted: coerced, rebuilt from allowlists (per studio), checked against approved facts in Affiliate Studio, never able to approve anything; the import fetch has a host allowlist, timeout and size cap.
- [ ] Web uses semantic, accessible production markup (WCAG 2.2 AA); radio groups follow the APG pattern; focus is visible everywhere.
- [ ] Reference viewports (1440 × 900, 390 × 844) are comparison targets, never fixed containers; no horizontal page scroll from 360px.
- [ ] Controls whose targets are not specified (`needs-spec:`) are not rendered; no “coming soon”.
- [ ] The app is wired through `MONGODB_URI` without its value appearing anywhere; secrets (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `DEEPSEEK_API_KEY`, `ELEVENLABS_API_KEY`, AWS keys, JWT secret) are read through the validated runtime config only.
- [ ] The database is seeded (demo account bound to `SEED_OWNER_EMAIL` + display data) before any demo.
- [ ] (Batch 2) Voice and render work never runs in the API process or in a request; the media worker isolates it with leases, a hard render limit and per-job temp directories.
- [ ] (Batch 2) In Affiliate Studio every line a viewer reads is claim-checked; in both studios rights are confirmed per upload, and exports are immutable snapshots.
- [ ] (§3.23) Studios come from the studio registry, and shared code never branches on a studio by name; shared surfaces are studio-neutral; Affiliate Studio's screens, prompts and outputs are unchanged by Entertainment Studio; a story never needs a product, link or fact; every character photo carries its own consent confirmation.
- [ ] (§3.25) A story continues as episodes: each episode is its own project; Next episode only from the latest approved episode, free and idempotent; copies never change earlier episodes; continuity reaches the model through recaps and the previous episode, never through client state; every non-final episode ends on a cliffhanger and a final one resolves; Episode 1 and Affiliate prompts are unchanged.
